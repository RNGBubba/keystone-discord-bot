## What changed

feature.

### The prose gate

`memory/machine/claims.json` is the new contract. It names the documents that
speak in the present tense — `AGENTS.md`, `README.md`, the four governance files
and the product halves of the vault — and the capabilities that have no code yet.
`memory/tools/memory-check.mjs` now:

- recomputes roots, subcommands, actions, context menus, modules, tests and
  passes from `commands.json`, `project.json`, the vitest JSON report and
  `passes.json`;
- checks those counts in every governed document, with a deliberate distinction:
  a sentence that says `at pass 41`, `then-current`, `was` or a dated live run is
  history; a sentence that says `now`, `current` or `today` is a claim about
  today and must match. The distinction is visible in the failure message, so a
  writer can fix the sentence instead of guessing at the regex;
- scans capability claims against code evidence. Components V2 (`packages/ui`,
  an `IsComponentsV2` adapter flag), i18n (`packages/i18n`) and the Next.js
  dashboard shell have no evidence, so every mention must say planned, future,
  open, later or not shipped;
- rejects a governed page that calls the live compose services stopped while
  `machine/live.json` records Postgres and Redis reachable;
- cross-checks `commands.json` against `project.metrics`, so the prose points at
  a generated file that points at the same registry the bot registers.

The rule is not "no numbers in prose". It is "no number in the present tense
that the machine cannot reproduce".

## What we tried and rejected

- **Scan every Markdown file, including journals and the pass ledger.** Rejected:
  history is supposed to contain old counts. A gate that treats a journal as a
  present-tense claim would force us to rewrite history instead of labelling it.
- **Line-only matching.** Rejected: a sentence wraps. The first version missed a
  wrapped "now reports 20 roots / 138" and flagged a `P7 Context menus` heading
  as seven menus. The window is now one line either side, with a lookbehind for
  `P7` and for digits inside a larger number.
- **Treat every "N tests" as the suite.** Rejected: module pages legitimately
  say "6 tests" about their own file, and `vitest run modules/setup/src` reports a
  subset. Only the "N tests / M files" and "N tests in M files" forms are global.
- **Treat every "N roots" as the ledger.** Rejected: a module may own three of
  the hundred. The gate requires the ledger phrasing (`20/100 roots`, `Registry N
  roots`, `ledger is N roots`) and skips "for this module" and "of Discord's".
- **Hardcode the current numbers in the checker.** Rejected: that would create a
  second source of truth. The numbers come from the same generated files the bot
  and the budget use.
- **Add a `packages/ui` stub so the V2 mentions pass.** Rejected: the gate exists
  to stop a claim outrunning the code, not to give it a hollow building. The
  capability stays planned.
- **Edit `Pass-Ledger.md` directly.** Rejected: it is generated. The pass was
  added to `passes.json` and rendered.
