# Pass 62 — P7: command descriptions and replies come from one typed catalog

**Date:** 2026-11-03
**Phase:** P7
**Carrier:** `packages/i18n` (the catalog), `apps/bot/src/adapt.ts` (the Discord
localization map) and the command modules. No new package, table, command or
translation service.

## What changed

- **Every registered description has a key.** `packages/i18n/src/command-copy.ts`
  holds 253 keys generated once from the live registry: 20 roots, 141
  subcommands and 92 distinct option names. The German beside each key is
  written prose, reviewed as part of this pass, not a machine translation. The
  English object is the type source and the German object is declared
  `typeof commandCopyEn`, so a missing or differently-argued key does not
  compile.
- **Replies for the covered flows.** The English catalog gains member-facing
  reply keys for `/ping`, `/about`, `/help` (browse, commands, search, privacy,
  changelog), `/rank` (leaderboard, rewards, admin, balance, daily, pay, shop,
  buy, gamble, ledger, season), `/ticket` (panel, open, stats, claim, close,
  add, transcript, summary) and the `Rank card` user menu. The shared
  community helper's guild-only and permission refusals take the caller's
  locale, so a missing `ManageGuild` answers in German on those flows.
- **One adapter fix the coverage test found.** `localizeCommand` collected
  option names and applied each description to the first matching JSON node.
  `/help browse` and `/help commands` both declare a `module` option, so the
  second node never carried a German description. The function now walks each
  subcommand's own option nodes, and the coverage test is what caught it.
- **Enforcement, not memory.** `apps/bot/src/command-localization.test.ts` now
  derives the expected key set from the live registry and checks both
  directions: every root, subcommand and option has a German string that is not
  the English one, and no `command.*` key survives for a command that was
  renamed or removed. The same file classifies every file in
  `modules/diagnostics/src/commands` and `modules/community/src/commands` as
  translated or deliberately English-only, then scans the translated files for
  reply literals (`content:`, `title:`, `UserError(`). A new command file fails
  the test until someone decides, in the source, whether it is translated or
  named as English-only. Two lines carry an `i18n-exempt` comment: the product
  name and the transcript's code fence around stored ticket text.
- **The probe.** `command-copy-localization` drives the real `dispatchCommand`
  with a plain `InteractionLike` on Postgres: with `setup.locale=de` all 384
  description nodes across the 20 chat-input roots carried German, `/ping`,
  `/about` and `/help browse` replied in German, a key no catalog defines
  returned the fallback sentence, a partial catalog fell back to English, and
  resetting the setting restored the English reply.

## What is still English, and why

The pass translates what ships, not everything that exists. The remainder is
named here so the next slice is unambiguous:

- **Admin configuration replies in `modules/community/src/commands/tools.ts`**
  (embeds, tags, reminders, giveaways, polls, panels, starboard, birthdays,
  suggestions, sticky, auto-responder). These are operator-facing setup copy and
  were not reviewed as prose in this pass; they are in the test's English-only
  map with this reason.
- **The other ten modules' command replies** (`ai`, `analytics`, `events`,
  `forms`, `invites`, `logging`, `moderation`, `modmail`, `music`, `setup`).
  Their command descriptions *are* translated, because those come from the
  registry-derived keys; only the replies are still English.
- **Kernel copy**: the guild-only guard message, the generic command-failure
  sentence and the redaction path live in `packages/kernel`, which has no locale.
- **Service-owned failure reasons** (`EconomyService`'s "Daily already
  claimed…", "You already own that role.", spend refusals): the catalog wraps
  the balance but does not translate the reason, so a German member can still
  see an English sentence from the economy service. Translating those belongs
  with the service that owns the rule, not with the command.
- **Operator-owned text by design**: welcome/goodbye greetings, admin-written
  embeds and anything a guild supplies. These must never be translated.

## What we tried and rejected

- **Generating the German mechanically and reviewing later.** Rejected: the
  pass exists because machine-translated prose is worse than English. The
  generator wrote the English keys from the registry; the German was written by
  hand in the catalog.
- **Translating only command descriptions.** Rejected: a German guild would get
  a German `/rank` description and an English reply, which is the drift the pass
  is meant to remove. The covered flows include their main replies.
- **A regex-only test that every reply literal is gone from every module.**
  Rejected: ten modules' admin replies are legitimately still English, and an
  allowlist of a hundred lines is a weaker signal than the per-file decision
  map. The map grows one review at a time.
- **Passing a locale into `settingsFor`/`port` as well.** Rejected: both throw
  only on a misconfigured process, not on user input; the guild-only refusal is
  already translated where a user can hit it (`/ping`'s DM path, `settingsFor`).
- **Storing the German in a JSON file beside the catalog.** Rejected: the
  catalog's typed functions are what make an omitted interpolation or a changed
  plural argument a compile error; JSON would lose that.
