# Pass 65 — P7: contain the component seams the audit named

**Date:** 2026-11-03
**Phase:** P7
**Carrier:** `apps/bot/src/components.ts`, two new adapter route files, the
community and moderation modules, `packages/kernel/src/components.ts` and
`scripts/live-probe.ts`. No command, table, reply, check id or count changed.

This is a containment pass, not a capability pass. It moves three structural
seams the pass-64 audit named and leaves every observable path where it was.

## What changed

- **The route table is now per module.** `apps/bot/src/form-interactions.ts`
  owns the form Apply/submit/review routes, and
  `apps/bot/src/community-interactions.ts` owns the ticket, role, role-select,
  giveaway, suggestion and poll routes. Each exports one
  `register*Routes(router, deps)` function beside the moderation adapter's
  `registerModerationRoutes`. [`apps/bot/src/components.ts`](../../apps/bot/src/components.ts)
  is now dependency types, the three registration calls and the gateway
  listener; it contains no module handler. The handlers, replies, permissions,
  clocks and service calls were copied unchanged, including the ticket's
  payload-guild check and the form's modal TTL.
- **One signer concept in the kernel.** `PanelSigner` and `requirePanelSigner`
  now live in `packages/kernel/src/components.ts` beside `ComponentSigner`.
  `modules/community/src/panels.ts` re-exports them for its own files, and
  moderation's `ModerationSigner` alias is gone: `cases.ts`, `security.ts`,
  `mod/` and `verify/` all use the kernel type and the kernel refusal. The one
  refusal sentence is the community one, **"Interactive panels are not
  configured on this bot."** This is the only user-visible string that changed,
  and only in a composition that was built without a signer; every normal path
  is byte-identical.
- **One probe fake.** `scripts/live-probe.ts` now has a single
  `probeComponent()` factory that builds the structural interaction, runs it
  through `asComponentInteraction` and captures replies/modals. The form,
  community and moderation blocks keep thin wrappers with their old default
  user/channel/guild so their call sites did not move. The newest fake's
  `guildId: null` support is now the helper's behaviour for every block, so the
  DM case cannot drift from the others again.
- **The boundary chosen:** module packages own the data, services and panel
  builders; `apps/bot/src/*-interactions.ts` own the transport routes; the
  kernel owns the signer contract, signature/expiry/guild routing and the
  refusal; `components.ts` owns composition and the single gateway listener.
  Routes deliberately did not move into `modules/*`: that would pull
  `ComponentRouter` and interaction plumbing into the domain packages, which
  `AGENTS.md` keeps in the app adapters.

## What we tried and rejected

- **Putting the routes inside `modules/*`.** Rejected: the modules already mint
  ids and render panels, but routing an interaction is an adapter concern. The
  kernel-inward rule and the existing moderation precedent both point at
  `apps/bot/src/*-interactions.ts`.
- **Keeping `ModerationSigner` as an alias.** Rejected: it would leave two names
  for one contract, which is exactly the duplication the audit found.
- **Keeping community's local `requirePanelSigner` wrapper.** Rejected: a
  re-export is enough for the module's import surface; the implementation and
  the message belong in the kernel.
- **One shared `ComponentRuntimeDeps` for every registrar.** Rejected: each
  registrar now takes only its own store, settings and signer, so a module
  cannot reach another module's ports.
- **Rewriting every probe call site to the helper.** Rejected: three thin
  wrappers preserve the existing `button`/`modal`/`click`/`press` shapes and
  prove the move is behavior-neutral; the duplicate fake bodies are gone.
