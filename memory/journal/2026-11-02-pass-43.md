checkable and corrects the ones that had drifted.

- Computes the registry from the same module list the bot uses: roots,

## What we tried and rejected

- **Rewrite the old journals and acceptance evidence.** Rejected. A journal is a
  timestamped record; editing pass 40 to say it knew about Docker would be a
  worse lie than the stale sentence. Historical counts are qualified with their
  pass instead, and the new `Now` section states the current truth.
- **Hard-code the expected numbers in `audit:claims`.** Rejected. The script
  imports the registry, so a new root or subcommand changes the expected value
  automatically; only the prose has to follow.
- **Lint every sentence in the vault.** Rejected. A generic prose linter would be
  noisy and would fight legitimate historical writing. The audit owns
  current-tense counts, the latest-pass pointer, module paths and the V2 claim.
  The rest is checked by `memory:check` structurally.
- **Add a stub `packages/ui` so the V2 claims become true.** Rejected. A package
  that exports nothing would make a green audit and a false product. The honest
  state is "planned", which is what the docs now say.
- **Generate the changelog from `passes.json` at build time.** Rejected for this
  pass. The bot's production bundle does not ship the memory directory, so a
  runtime read would fail in Docker. A small typed `changelog.ts` plus an audit
  is simpler and works in every deployment; a build-time generator can replace it
  when the docs pipeline exists.
- **Create the whole completion program board (`program.json`, scorecard,
  human-todo) in this pass.** Deferred. This step is truth only. The approved
  mission's next passes create those files; the `nextAction` field keeps the
  handoff explicit.
