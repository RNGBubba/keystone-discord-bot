# Pass 58 — P7 Components V2 layer, signed component routing and form modals

**Date:** 2026-11-03
**Phase:** P7
**Carrier:** a new framework-free `packages/ui` plus `apps/bot/src/components.ts`.
The package has no discord.js, zod or I/O; `adapt.ts` remains the only file that
knows a discord.js builder.

## What changed

- **`packages/ui` exists.** The vault's P7 bullet named a Components V2 budgeter,
  primitives and modal Label support; this is that package. `layout()` builds a
  typed container / text display / separator / section / action row tree and
  enforces Discord's 40-component and ~4,000-character budgets plus the shape
  rules Discord rejects at runtime (five buttons per row, a select alone in its
  row, 1–25 options, link-vs-custom-id buttons, 1–10 container children, 1–3
  section texts, non-link section accessories). `modal()` builds a title plus
  one Label per text input, capped at five inputs, 45-character titles/labels
  and 4,000-character inputs. Both throw `LayoutError` with the offending value;
  nothing is silently truncated.
- **Kernel owns the component contract.** `V2Component` and `ModalSpec` are
  structural types in the kernel; `ReplyInput.v2` is mutually exclusive with
  `content`, `embeds` and legacy rows, and the adapter sets
  `MessageFlags.IsComponentsV2` only for that shape. `createComponentSigner`
  mints and verifies `k1:<sig>:<exp>:<namespace>:<action>:<payload>` ids — an
  HMAC over namespace, action, expiry and payload, at most 100 characters.
  `ComponentRouter` matches namespace + action + kind, refuses a missing
  signature, an expiry, a missing guild or a route permission before the handler
  runs, and turns a handler's `UserError` into an ephemeral refusal.
- **One component listener.** `registerComponentInteractions` handles buttons,
  string selects and modal submits. Moderation's pre-existing
  `keystone:appeal:` / `keystone:verify:` ids are handed to their existing
  handler; every new panel goes through the router. The old moderation-only
  listener is gone.
- **Form panels are V2 and the Apply button is real.** `/form panel` defers, then
  edits in a container with signed Apply and staff buttons. Apply opens a modal
  built from the form's fields (up to five) and a signed 15-minute modal id; a
  valid submit calls the same `FormService.submit` as the command path, and a
  missing required answer is refused with the field name. A form with more than
  five questions keeps the `/form submit` path and the button says so. The staff
  button requires `ManageGuild` and lists the pending queue.
- **`INTERACTION_SECRET` is optional.** Without it the bot mints a per-process
  key, so panels from before a restart are stale (the honest behaviour) rather
  than sharing a default secret across deployments. `.env.example` documents it.
- **Tests.** A new PGlite-free UI suite, kernel codec/router tests, adapter tests
  for V2 JSON and modal fields, and bot route tests. The form command test now
  asserts the layout tree, not an embed.

## What we tried and rejected

- **A `packages/ui` that imports discord.js.** Rejected: the kernel stays inward
  and the adapter is the only discord.js file. The package emits structural
  nodes; one conversion function in `adapt.ts` maps them to builders.
- **Unsigned component ids with an expiry only.** Rejected: anyone could extend
  an expiry or point a button at another guild's record. The HMAC makes the id
  tamper-evident, and the router checks it before the handler.
- **A database table of open panels.** Rejected for this slice: a signed expiry
  needs no round trip and no cleanup job. A panel that must survive a restart
  already does — the message is the record.
- **A shared default signing secret.** Rejected: a constant secret in a public
  repo is not a secret. A per-process key is weaker but honest, and the env var
  makes the durable choice explicit.
- **Relaxing the modal id rule to lowercase.** Rejected after the first test run:
  signed ids are mixed-case base64url with colons. Discord accepts any 1–100
  character id without whitespace, so the builder now enforces that instead of a
  rule our own ids cannot satisfy.
- **Letting `/form panel` stay an embed and adding buttons beside it.** Rejected:
  the point of the pass is one V2 layout path. The panel is one container; the
  legacy embed is gone.
- **Opening a second modal from a modal submit.** Not possible in Discord. A
  bad submit replies with the missing field and the user presses Apply again;
  the test and the probe assert that message, and the journal records the limit.
- **Migrating every existing panel now.** Rejected for this slice. Rank cards,
  welcome/goodbye and ticket panels still use embeds; the component layer is
  available and the vault marks them as the next migration, not as done.

## Verification

- `pnpm typecheck` — pass.
- `pnpm test` — **604 tests in 89 files**.
- `pnpm probe:live` — **24/24**, adding `web-component-panels` over the real
  discord.js adapter and the signed router on Postgres: the panel rendered as a
  V2 container with signed Apply and staff ids; Apply opened a modal with the
  form's title and two inputs; a valid submit wrote one `form_submissions` row;
  a submit missing `tz` was refused with the field name and wrote nothing; an
  expired id was refused before the handler and opened no modal; a member
  without `ManageGuild` was refused while a manager saw the one pending
  application. The probe constructs discord.js objects and passes them through
  `asComponentInteraction`; **a live gateway click, right-click or slash command
  is not claimed.**
- `pnpm check` — green after memory is updated.
- `pnpm build` — green.

## Next

P7's remaining UI work is i18n (`packages/i18n`, typed keys, per-guild locale,
command localizations) and migrating the remaining embeds (rank card,
welcome/goodbye, ticket panel) onto `packages/ui`. Live gateway proof of a click
and a modal submit still needs a human Discord client.
